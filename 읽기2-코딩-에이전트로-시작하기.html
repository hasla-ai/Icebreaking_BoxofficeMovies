읽기 2

웹 채팅에서 코딩 에이전트로 넘어가 첫 작업을 하고, 오래 쓰기 위해 알아 둘 기능을 살펴보는 여섯 단원입니다.

웹 채팅으로도 HTML 페이지 한 장은 충분히 만들 수 있습니다. 원하는 것을 설명하고, 나온 코드를 받아 저장하고, 열어 보고, 고칠 점을 다시 말하면 됩니다. 그런데 파일이 여러 개로 늘고 고치는 일이 반복되면, 코드를 복사해 붙여 넣고 다시 설명하는 일이 점점 번거로워집니다.

이때 쓸 수 있는 것이 코딩 에이전트입니다. 코딩 에이전트는 내 컴퓨터의 작업 폴더에서 파일을 직접 읽고, 고치고, 실행해 확인까지 이어 가는 AI입니다. 이 글에서는 웹 채팅 대신 코딩 에이전트를 쓸 때 무엇이 달라지는지, 처음에는 어떻게 시작하는지, 그리고 오래 쓰기 위해 알아 둘 기능은 무엇인지 차례로 살펴봅니다.

코딩 에이전트마다 화면과 기능 이름은 조금씩 다릅니다. 사용 중인 제품의 설정과 사용법은 ‘코딩 에이전트별 안내’ 상자에서 찾아볼 수 있습니다. 화면이나 메뉴가 설명과 다르다면, 해당 제품의 공식 안내에서 현재 사용법을 확인합니다.

01웹 채팅과 코딩 에이전트

웹 채팅 대신 코딩 에이전트를 쓴다면?

생각 열기

대화창에 나온 코드를 복사해 저장하는 일, 파일이 다섯 개로 늘어나도 괜찮을까요?

해 보기웹 채팅으로 페이지를 만들 때 사람이 직접 하는 일을 모두 적어 봅시다.

학습 목표
  1. 웹 채팅과 코딩 에이전트에서 만드는 순서는 같고 일하는 자리가 다르다는 것을 설명할 수 있다.
  2. 코딩 에이전트로 넘어가면 좋은 상황을 말할 수 있다.
1-1

만드는 순서는 같습니다

웹 채팅을 쓰든 코딩 에이전트를 쓰든 만드는 순서는 같습니다. 먼저 무엇을 만들지 정리하고, AI에게 만들게 하고, 직접 열어 확인한 뒤, 고칠 점을 다시 요청합니다. 코딩 에이전트를 쓴다고 해서 이 흐름이 바뀌지는 않습니다.

무엇을 만들지 정리한 짧은 문서를 이 글에서는 기획서라고 부르겠습니다. 기획서에는 누가 쓰는지, 무엇을 하려는지, 화면과 동작은 어떠한지, 필요한 자료는 무엇인지, 무엇이 되면 완성인지 다섯 가지를 적습니다. 마크다운으로 적어 기획서.md로 저장해 두면 웹 채팅에서든 코딩 에이전트에서든 다시 꺼내 쓸 수 있습니다.

1-2

달라지는 것은 일하는 자리입니다

웹 채팅에서는 대화창이 일하는 자리입니다. AI가 대화창에 코드를 보여 주면, 사람이 그 코드를 파일로 저장하고 브라우저로 열어 봅니다. 고칠 때는 다시 대화창으로 돌아가 설명하고, 바뀐 코드를 받아 파일을 바꿉니다.

코딩 에이전트에서는 작업 폴더가 일하는 자리입니다. AI가 폴더 안의 파일을 직접 읽고 고칩니다. 코딩 에이전트에 따라서는 명령을 실행하거나 브라우저로 페이지를 열어 결과를 확인하는 데까지 이어 갑니다. 사람은 파일을 옮기는 대신, 무엇을 바꿀지 정하고 바뀐 결과를 확인하는 데 집중합니다.

비교할 점 웹 채팅 코딩 에이전트
일하는 자리 대화창 내 컴퓨터의 작업 폴더
파일 저장 사람이 코드를 복사해 저장 AI가 폴더 안의 파일을 직접 만들고 고침
확인 사람이 파일을 열어 확인 AI가 실행해 볼 수 있고, 사람도 직접 확인
매번 하는 설명 대화마다 다시 설명 작업 지침 파일에 적어 두면 매번 읽음
1-3

언제 넘어가면 좋을까요

웹 채팅으로 충분한 작업도 많습니다. 짧은 페이지 한 장을 한두 번 고칠 정도라면 굳이 코딩 에이전트로 넘어갈 필요가 없습니다. 다음과 같은 일이 잦아진다면 코딩 에이전트를 써 볼 만합니다.

  • 파일이 여러 개로 늘어 코드를 옮기는 일이 번거로울 때
  • 같은 페이지를 계속 개선해 갈 때
  • 고친 뒤 직접 열어 확인하는 일까지 맡기고 싶을 때
  • 매번 같은 설명을 반복하고 있을 때

핵심 정리

  1. 무엇을 만들지 정리하고, 만들게 하고, 직접 열어 확인하고, 고칠 점을 다시 요청하는 순서는 웹 채팅에서든 코딩 에이전트에서든 같습니다.
  2. 웹 채팅은 대화창에서, 코딩 에이전트는 내 컴퓨터의 작업 폴더에서 일합니다. 코딩 에이전트는 폴더 안의 파일을 직접 만들고 고칩니다.
  3. 파일이 늘거나, 같은 페이지를 여러 번 고치거나, 같은 설명을 반복할 때 코딩 에이전트를 써 볼 만합니다.

확인하기

  1. 1O / X

    코딩 에이전트를 쓰면 무엇을 만들지 정리하고 결과를 확인하는 순서가 필요 없어진다.

    정답과 풀이
    정답 X웹 채팅을 쓰든 코딩 에이전트를 쓰든 만드는 순서는 같습니다. 코딩 에이전트를 쓴다고 해서 이 흐름이 바뀌지는 않습니다.
  2. 2고르기

    웹 채팅과 코딩 에이전트의 차이로 알맞은 것은?

    정답과 풀이
    정답 ②웹 채팅에서는 사람이 코드를 복사해 저장하지만, 코딩 에이전트에서는 AI가 폴더 안의 파일을 직접 만들고 고칩니다. 확인은 사람도 직접 합니다.
02첫 작업 시작하기

코딩 에이전트는 어떻게 시작할까?

생각 열기

코딩 에이전트를 처음 열었는데 무엇부터 해야 할지 모르겠다면, 누구에게 물어보면 될까요?

해 보기코딩 에이전트에게 처음 보낼 질문을 한 문장으로 적어 봅시다.

학습 목표
  1. 코딩 에이전트에게 사용법을 묻고, 계획 모드에서 질문에 답하며 첫 작업을 시작할 수 있다.
  2. 승인 요청을 읽고 판단하며, 결과가 마음에 들지 않을 때 되돌리거나 고쳐 달라고 요청할 수 있다.
  3. 민감정보·원본 파일·외부 전송과 관련해 피해야 할 행동을 말할 수 있다.
2-1

코딩 에이전트를 고르고 작업 폴더를 만듭니다

코딩 에이전트는 여러 회사에서 내놓고 있습니다. OpenAI의 Codex, Anthropic의 Claude Code, Google의 Antigravity가 대표적입니다. 요즘은 데스크톱 앱을 내려받아 작업 폴더를 고르고, 웹 채팅처럼 대화하며 요청하는 방식으로 시작할 수 있습니다.

코딩 에이전트를 골랐다면 작업 폴더를 하나 만듭니다. 코딩 에이전트는 이 폴더 안에서 일합니다. 폴더에는 지금 만들 결과물과 관련된 파일만 둡니다. 개인 문서나 비밀번호가 담긴 파일이 같은 폴더에 있으면 AI가 그 파일까지 읽을 수 있습니다.

CodexClaude CodeAntigravity

코딩 에이전트별 안내 Codex는 ChatGPT 데스크톱 앱에서 Codex 탭으로, Claude Code는 Claude 데스크톱 앱에서 Code 탭으로 바꿔 씁니다. Antigravity는 Antigravity 앱을 내려받아 씁니다. 어느 쪽이든 앱에서 작업 폴더를 고른 뒤 시작합니다. 비용도 확인합니다. Antigravity는 무료로 쓸 수 있고(사용량 한도 있음), Codex와 Claude Code는 ChatGPT나 Claude의 유료 구독이 필요합니다. 앱은 ChatGPT 다운로드, Claude 다운로드, Antigravity 다운로드 페이지에서 내려받습니다.

2-2

모르는 것은 코딩 에이전트에게 먼저 묻습니다

작업 폴더를 고르고 나면 무엇부터 해야 할지 막막할 수 있습니다. 이때 가장 좋은 첫 요청은 코딩 에이전트에게 사용법을 직접 묻는 것입니다. 코딩 에이전트도 AI이므로, 처음이라는 것과 개발을 전혀 모른다는 것을 솔직하게 말하면 눈높이에 맞춰 설명해 줍니다.

설명을 듣다가 모르는 말이 나오면 그 말도 다시 물어봅니다. “작업 폴더가 뭐야?”, “승인해 달라는 게 무슨 뜻이야?”처럼 묻는 것도 좋은 요청입니다. 웹 채팅에서 모르는 것을 물어보던 것과 똑같이 하면 됩니다. 다만 설명이 지금 보이는 화면과 다를 수도 있습니다. 설명대로 되지 않으면 지금 화면에 무엇이 보이는지 말하고 다시 물어봅니다.

2-3

계획 모드를 켜고, AI가 먼저 묻게 합니다

사용법을 익혔다면 첫 작업을 시작합니다. 이 글에서는 한 장짜리 이력서 페이지를 예로 들겠습니다. 지원서에 링크로 붙이거나 처음 만나는 사람에게 나를 소개할 때 열어 보여 주는 페이지입니다.

처음부터 모든 것을 잘 설명하려고 애쓸 필요는 없습니다. 계획 모드를 켜고, 무엇을 만들고 싶은지 한두 문장으로 말한 뒤, 필요한 것은 AI가 먼저 물어보게 합니다. 계획 모드에서는 AI가 파일을 바꾸지 않고 계획부터 세웁니다.

AI는 누가 볼 페이지인지, 어떤 경력과 프로젝트를 넣을지, 휴대폰에서도 볼지 같은 것을 물어봅니다. 질문에 답하다 보면 기획서가 함께 만들어집니다. 정리된 기획서와 계획을 읽어 보고, 내 생각과 다른 점이 있으면 그 자리에서 바로잡은 뒤 “좋아, 이대로 만들어 줘”라고 요청합니다.

CodexClaude CodeAntigravity

코딩 에이전트별 안내 Codex, Claude Code, Antigravity 모두 파일을 바꾸기 전에 계획부터 세우는 계획 모드가 있습니다. 앱의 입력창 근처에서 모드를 바꿀 수 있으며, 정확한 위치는 각 앱의 안내에서 확인합니다.

2-4

승인을 요청하면 내용을 읽고 승인합니다

코딩 에이전트는 파일을 만들거나 고치기 전, 명령을 실행하기 전에 승인을 요청하기도 합니다. 이때 무엇을 하려는지 읽어 보고 승인합니다. 처음에는 모든 것을 자동으로 승인하기보다, 어떤 일을 하려는지 확인하며 쓰는 편이 안전합니다.

특히 작업 폴더 밖의 파일을 지우거나 고치려 할 때, 인터넷에서 무언가를 내려받으려 할 때는 정말 필요한 일인지 한 번 더 살펴봅니다. 무슨 뜻인지 모르겠다면 승인하기 전에 “이 명령이 무엇을 하는지 쉽게 설명해 줘”라고 물어볼 수 있습니다.

2-5

지켜야 할 안전 수칙

코딩 에이전트는 실제 파일을 바꾸거나 연결된 서비스에서 일을 할 수 있습니다. 편하게 맡기더라도 다음 다섯 가지는 하지 않습니다.

  • 비밀번호나 API 키를 대화창·기획서·HTML에 넣지 않습니다. API 키는 외부 서비스를 이용할 때 쓰는 비밀 인증값입니다. 필요한 설정은 해당 서비스의 공식 안내를 따르고, AI에게는 실제 값 대신 가짜 예시만 보여 줍니다.
  • 실제 민감정보로 테스트하지 않습니다. 주민등록번호·계좌번호·집 주소 대신 가상 자료를 사용합니다. 다른 사람의 개인정보가 담긴 파일을 작업 폴더에 두거나 AI에게 올리지 않습니다.
  • 모르는 명령이나 권한 요청을 그대로 승인하지 않습니다. 무엇을 바꾸는지, 작업 폴더 밖의 파일이나 외부 서비스에도 영향을 주는지 먼저 설명해 달라고 묻습니다. 내용을 읽지 않고 ‘모두 허용’을 누르지 않습니다.
  • 복사본 없이 원본을 지우거나 덮어쓰지 않습니다. 큰 변경 전에는 잘 동작하는 버전을 따로 저장합니다. “되돌려 줘”라는 요청만으로 항상 복구할 수 있는 것은 아닙니다.
  • 확인하지 않은 결과를 게시하거나 다른 사람에게 보내지 않습니다. 내용과 받는 사람, 공개 범위를 직접 확인하고 나서 전송합니다. GitHub에 올리기 전에도 비밀번호나 개인정보가 없는지 확인합니다.
2-6

결과를 확인하고, 다음 할 일도 AI에게 요청합니다

작업이 끝나면 AI가 무엇을 바꿨는지 보고합니다. 보고만 읽고 끝내지 말고 이력서.html을 브라우저로 직접 열어 봅니다. 휴대폰 화면에서도 열어 보고, 링크도 눌러 봅니다. 기획서의 완성 기준을 하나씩 대조하면 무엇을 더 요청할지 분명해집니다.

그다음 할 일도 AI에게 말로 요청하면 됩니다. 마음에 들지 않으면 이전으로 되돌려 달라고 하고, 더 좋게 만들고 싶으면 원하는 모습을 말합니다.

한 번에 완성하려 하기보다, 확인하고 요청하기를 여러 번 반복하며 조금씩 개선해 갑니다.

핵심 정리

  1. 작업 폴더에는 지금 만들 결과물과 관련된 파일만 둡니다. 같은 폴더에 있는 파일은 AI가 읽을 수 있습니다.
  2. 처음이라면 코딩 에이전트에게 사용법부터 묻습니다. 계획 모드를 켜고 만들고 싶은 것을 말하면, AI가 필요한 것을 묻고 답을 기획서로 정리합니다.
  3. 승인하기 전에 무엇을 하려는지 읽고, 끝나면 결과를 직접 열어 확인합니다. 마음에 들지 않으면 되돌리거나 고쳐 달라고 AI에게 요청합니다.
  4. 비밀번호·API 키는 대화창이나 결과물에 넣지 않습니다. 큰 변경 전에는 복사본을 남기고, 외부 공유는 내용을 확인한 뒤 합니다.

03AGENTS.md

매번 하는 설명은 어디에 적어 둘까?

생각 열기

새 대화를 열 때마다 “HTML 파일 하나로 유지해 줘”라고 다시 말하는 일을 어떻게 줄일 수 있을까요?

해 보기이력서 페이지를 고칠 때 매번 하게 될 말을 세 가지 적어 봅시다.

학습 목표
  1. AGENTS.md를 왜 쓰는지, 코딩 에이전트가 이 파일을 언제 읽는지 설명할 수 있다.
  2. 매번 지킬 지침과 이번에만 할 요청을 구분해, 행동으로 옮길 수 있는 지침을 쓸 수 있다.
3-1

같은 말을 매번 다시 하게 됩니다

이력서 페이지를 여러 번 고치다 보면 같은 말을 반복하게 됩니다. “HTML 파일 하나로 유지해 줘”, “전화번호와 집 주소는 넣지 마”, “고친 뒤에는 휴대폰 화면도 확인해 줘” 같은 말입니다.

한 대화 안에서는 AI가 이 말을 기억하더라도, 새 대화를 시작하면 앞에서 한 말을 알지 못합니다. 대화가 아주 길어지면 앞에서 한 말을 놓치기도 합니다. 그때마다 같은 말을 다시 하거나, 깜빡 빠뜨려 원하지 않는 결과를 받게 됩니다.

3-2

AGENTS.md에 적어 두면 매번 먼저 읽습니다

이렇게 매번 하는 설명을 적어 두는 파일이 AGENTS.md입니다. AGENTS.md는 코딩 에이전트가 그 폴더에서 일할 때 따라야 할 작업 지침을 적은 마크다운 파일입니다. 작업 폴더의 맨 위에 두면, 이 파일을 읽는 기능이 있는 코딩 에이전트는 대화를 시작할 때 먼저 읽습니다. 새 대화를 열어도 AGENTS.md는 폴더에 그대로 있으므로, 같은 말을 다시 하지 않아도 지침이 이어집니다.

사람이 매번 말로 전하던 것을 파일로 남겨 두는 셈입니다. 한 번 적어 두면 빠뜨릴 걱정이 줄고, 나중에 다른 코딩 에이전트로 작업하거나 다른 사람과 함께 작업해도 같은 지침을 읽게 할 수 있습니다.

3-3

무엇을 적으면 좋을까요

AGENTS.md에는 이 폴더에서 일할 때마다 지켜야 할 것을 적습니다. 꼭 지킬 것(개인정보를 넣지 않는다), 작업 방식(파일 하나로 유지한다), 고친 뒤 확인할 것(휴대폰 화면), 보고하는 방식(바꾼 내용과 확인하지 못한 내용)이 대표적입니다.

이번 한 번만 할 일은 적지 않습니다. “경력 부분을 표로 바꿔 줘”처럼 이번에만 할 요청은 대화에서 말하면 됩니다. AGENTS.md에는 다음 작업에서도 똑같이 지킬 것만 남깁니다.

지침은 “잘 확인해 줘”보다 “휴대폰 화면을 확인한다”처럼 행동으로 옮길 수 있게 씁니다. 그래야 AI도 따르기 쉽고, 사람도 지켜졌는지 확인하기 쉽습니다.

3-4

처음부터 다 쓰지 않아도 됩니다

AGENTS.md도 AI에게 만들어 달라고 할 수 있습니다. 이미 작업하던 폴더를 코딩 에이전트에서 열었다면, “이 폴더의 파일과 구조를 분석해서, 이 프로젝트의 작업 지침을 AGENTS.md로 만들어 줘”라고 요청하면 됩니다. AI가 만든 지침을 읽고 원하는 작업 방식과 다른 부분은 고칩니다. 새 폴더라면 만들려는 것과 지킬 조건을 AI가 먼저 물어보게 한 뒤, 답을 AGENTS.md로 정리해 달라고 요청합니다. 작업하면서 반복해서 설명하는 내용이 생기면 그때그때 한 줄씩 더합니다.

3-5

메모리와는 다릅니다

어떤 코딩 에이전트는 이전 대화에서 알게 된 유용한 내용을 기억해 두었다가 다음 작업에 참고하는 메모리 기능도 제공합니다. 예를 들어 짧고 담백한 문장을 좋아한다는 것을 기억해 두었다가 다음에 글을 쓸 때 반영하는 식입니다.

메모리는 기억을 보조하는 기능입니다. 무엇을 기억할지 AI가 고르므로, 꼭 지켜야 할 규칙이 남는다고 장담할 수 없습니다. 꼭 따라야 할 지침은 AGENTS.md에 직접 적어 둡니다.

AGENTS.md를 저장했다고 AI가 새로 학습하는 것도 아닙니다. 작업할 때마다 이 파일을 읽어 참고하는 방식입니다. 그래서 다른 폴더에서 일할 때는 그 폴더의 지침을 따로 마련해야 합니다. 지침이 잘 적용되는지 궁금하다면 “어떤 지침을 읽었고 이번 작업에 무엇을 적용할지 말해 줘”라고 물어볼 수 있습니다.

CodexClaude Code

코딩 에이전트별 안내 Codex는 작업 폴더의 AGENTS.md를 읽습니다. Claude Code는 같은 역할의 CLAUDE.md를 쓰며, CLAUDE.md가 없으면 AGENTS.md를 읽습니다. 메모리 기능을 켜고 끄는 방법은 각 앱의 설정 화면에서 확인합니다.

핵심 정리

  1. 새 대화에서는 AI가 앞에서 한 말을 알지 못합니다. 매번 하는 설명을 AGENTS.md에 적어 두면 대화를 시작할 때마다 먼저 읽습니다.
  2. AGENTS.md에는 이 폴더에서 일할 때마다 지킬 것을 행동으로 옮길 수 있게 적고, 이번에만 할 일은 대화에서 요청합니다. 처음부터 다 쓰지 않고 한 줄씩 더해도 됩니다.
  3. 메모리는 무엇을 기억할지 AI가 고르는 보조 기능입니다. 꼭 따라야 할 지침은 AGENTS.md에 직접 적습니다.

    정답과 풀이
    정답 ③AGENTS.md에는 다음 작업에서도 똑같이 지킬 것을 적습니다. 이번에만 할 요청은 대화에서 말하면 됩니다.
  2. 2O / X

04스킬

반복하는 일은 어떻게 묶어 둘까?

생각 열기

매번 같은 순서로 하는 확인을, 필요할 때만 꺼내 쓰는 매뉴얼로 묶어 둘 수 있을까요?

해 보기이력서를 고칠 때마다 반복하는 일을 순서대로 적어 봅시다.

학습 목표
  1. 스킬이 무엇이고 SKILL.md에 무엇을 적는지 설명할 수 있다.
  2. 스킬을 필요한 만큼만 단계적으로 읽는 방식과 스킬을 쓰는 두 가지 방법을 말할 수 있다.
  3. 스킬을 만드는 스킬의 역할을 설명하고 새 스킬을 요청할 수 있다.
4-1

스킬은 필요할 때 꺼내 쓰는 작업 매뉴얼입니다

이력서를 고칠 때마다 반복하는 일이 있습니다. 기획서를 읽고, 확인할 부분을 정하고, 직접 열어 보고, 결과를 기록하는 일입니다. 이 순서를 매번 긴 요청으로 설명하는 대신, 하나의 작업 방법으로 묶어 두고 필요할 때 꺼내 쓸 수 있습니다. 이렇게 묶어 둔 것이 스킬(Skill)입니다.

게임에서 캐릭터가 상황에 맞는 스킬을 골라 쓰듯, AI도 작업에 맞는 스킬을 골라 씁니다. 스킬은 특정 작업의 절차와 필요한 자료를 한 폴더에 담은 것입니다. 폴더에는 SKILL.md라는 안내 파일이 있고, 필요하면 참고 자료, 템플릿, 실행용 프로그램을 함께 둡니다.

맨 위 두 --- 사이에는 스킬의 이름(name)과 설명(description)을 적습니다. 설명에는 어떤 상황에서 이 스킬을 쓰는지 구체적으로 적습니다. 그 아래에는 실제 작업 순서를 적습니다.

4-2

필요한 만큼만 펼쳐 읽습니다

스킬이 여러 개 있어도 AI가 처음부터 모든 내용을 읽지는 않습니다. 처음에는 스킬의 이름과 설명만 목록으로 훑어봅니다. 요청이 어떤 스킬의 설명과 맞으면 그 스킬을 고르고, 그때 SKILL.md의 작업 순서를 펼쳐 읽습니다. 작업하다 템플릿이나 참고 자료가 필요해지면 그 자료를 더 읽습니다.

이렇게 필요한 만큼만 단계적으로 읽으면 AI가 참고할 수 있는 공간을 아낄 수 있습니다. AI가 한 번에 참고할 수 있는 정보에는 한계가 있으므로, 쓰지 않을 스킬의 내용까지 모두 펼쳐 두지 않는 것입니다. 스킬의 설명을 구체적으로 써야 하는 이유도 여기에 있습니다. AI는 설명을 보고 이 스킬이 지금 필요한지 판단합니다.

4-3

스킬을 쓰는 두 가지 방법

스킬을 사용하는 방법은 두 가지입니다. 첫째, 평소처럼 말로 요청합니다. 요청이 스킬의 설명과 맞으면 AI가 스스로 그 스킬을 골라 씁니다. 둘째, 스킬 이름을 직접 지정해 요청합니다. 써야 할 스킬이 분명할 때 가장 확실한 방법입니다.

CodexClaude Code

코딩 에이전트별 안내 Codex는 작업 폴더의 .agents/skills 폴더에서 스킬을 찾고, 입력창에 $스킬이름을 써서 직접 부를 수 있습니다. Claude Code는 .claude/skills 폴더의 스킬을 쓰고, 입력창에 /스킬이름을 써서 직접 부를 수 있습니다.

4-4

스킬을 만드는 스킬도 있습니다

반복하는 작업을 새 스킬로 묶고 싶다면, 스킬을 만드는 스킬을 사용할 수 있습니다. Codex의 skill-creator가 그 예입니다.

이 제작용 스킬에는 무엇을 하는 스킬인지와 언제 사용할지 묻고, 작업 순서와 필요한 자료를 정해 SKILL.md를 작성하는 절차가 들어 있습니다. AI는 이 절차를 읽고 필요한 것을 질문한 뒤, 답을 바탕으로 새 스킬의 폴더와 파일을 만듭니다.

핵심 정리

  1. 스킬은 특정 작업의 절차와 필요한 자료를 한 폴더에 담은 것이며, SKILL.md에 이름과 설명, 작업 순서를 적습니다.
  2. AI는 처음에 스킬의 이름과 설명만 훑고, 요청에 맞는 스킬을 고른 뒤에 작업 순서와 추가 자료를 펼쳐 읽습니다.
  3. 스킬은 AI가 요청에 맞춰 고르게 하거나, 이름을 직접 지정해 사용합니다.
  4. 새 스킬은 제작용 스킬에 만들고 싶은 일을 설명해 만들 수 있습니다.

다른 서비스와는 어떻게 연결할까?

생각 열기

노션의 회의록을 읽고 슬랙에 공유하는 일까지 AI에게 맡기려면, 무엇이 더 필요할까요?

해 보기AI와 연결하고 싶은 서비스 하나와, 그 서비스에서 맡기고 싶은 일을 적어 봅시다.

학습 목표
  1. MCP가 에이전트를 외부 서비스와 잇는 공통 규칙이라는 것을 설명할 수 있다.
  2. 서비스를 연결할 때 권한을 필요한 만큼만 주고, 되돌리기 어려운 일은 먼저 확인할 수 있다.
5-1

MCP는 외부 서비스와 잇는 공통 규칙입니다

코딩 에이전트는 기본적으로 작업 폴더 안의 파일을 다룹니다. 그런데 일을 하다 보면 폴더 밖의 정보가 필요할 때가 있습니다. 노션에 적어 둔 회의록을 읽거나, 정리한 내용을 슬랙에 올리거나, 일정표를 확인하는 일입니다.

이렇게 에이전트를 외부 서비스와 연결하는 공통 규칙이 MCP(Model Context Protocol)입니다. 서비스마다 연결 방식이 제각각이면 코딩 에이전트마다 따로 맞춰야 하지만, 공통 규칙이 있으면 한 번 만든 연결을 여러 에이전트가 같은 방식으로 쓸 수 있습니다. 여러 기기를 같은 모양의 충전 단자로 연결하는 것과 비슷합니다.

5-2

요즘은 연결만 하면 됩니다

MCP를 직접 다룰 일은 많지 않습니다. 요즘 코딩 에이전트 앱은 플러그인이나 커넥터라는 이름으로 연결할 서비스를 고르게 하고, 사용자가 권한을 허용하면 연결이 끝납니다. 연결한 뒤에는 평소처럼 부탁하면 됩니다.

연결한 서비스에서는 AI가 내 계정으로 글을 읽고 쓸 수 있습니다. 그러므로 꼭 필요한 서비스만 연결하고, 허용하는 권한도 필요한 만큼만 줍니다. 글을 올리거나 지우는 일처럼 되돌리기 어려운 일은 실행하기 전에 내용을 먼저 보여 달라고 요청합니다.

CodexClaude Code

코딩 에이전트별 안내 Codex는 앱의 Plugins 탭에서, Claude Code는 입력창 옆 + 버튼의 커넥터 메뉴에서 연결할 서비스를 고르고 권한을 허용합니다. 명령어를 직접 입력할 필요는 없습니다.

핵심 정리

  1. MCP는 에이전트를 외부 서비스와 연결하는 공통 규칙으로, 한 번 만든 연결을 여러 에이전트가 같은 방식으로 쓸 수 있게 합니다.
  2. 요즘 코딩 에이전트 앱에서는 플러그인이나 커넥터에서 서비스를 고르고 권한을 허용하면 연결되고, 그 뒤에는 평소처럼 부탁합니다.
  3. 연결한 서비스에서는 AI가 내 계정으로 읽고 쓰므로, 필요한 서비스와 권한만 주고 되돌리기 어려운 일은 먼저 내용을 보여 달라고 합니다.

06서브에이전트

일을 나누어 맡기려면?

생각 열기

내가 만든 이력서를 처음 보는 사람의 눈으로 다시 읽으려면 어떻게 해야 할까요?

해 보기누군가에게 따로 맡기고 싶은 일을 하나 떠올리고, 그 사람에게 무엇을 건넬지 적어 봅시다.

학습 목표
  1. 컨텍스트 윈도우를 책상에 비유하고, 서브에이전트가 새 책상에서 따로 일한다는 것을 설명할 수 있다.
  2. 서브에이전트에게 맡기면 좋은 두 가지 경우를 말하고, 돌려받은 결과를 직접 확인할 수 있다.
6-1

서브에이전트는 새 책상에서 따로 일합니다

AI가 한 번에 참고할 수 있는 정보의 범위를 컨텍스트 윈도우(Context Window)라고 합니다. 책상에 비유하면, 지금 펼쳐 놓고 참고하는 자료가 놓인 책상의 크기입니다. 대화가 길어지고 읽은 파일이 늘어날수록 책상 위가 붐빕니다.

서브에이전트(Subagent)는 메인 에이전트가 떼어 준 일 하나를 자기 책상에서 따로 하고, 결과만 돌려주는 에이전트입니다. 서브에이전트는 메인 에이전트의 책상에 쌓인 대화와 생각을 그대로 보지 않습니다. 메인 에이전트가 건넨 자료와 기준만 받아 새 책상에서 시작합니다. 그래서 맡길 때는 무엇을 보고 무엇을 돌려줄지 분명히 알려 주어야 합니다.

6-2

언제 맡기면 좋을까요

서브에이전트가 특히 도움이 되는 경우는 두 가지입니다.

첫째, 객관적인 눈이 필요할 때입니다. 내가 쓴 글은 내 눈에는 다 맞아 보입니다. 같은 대화에서 만든 AI도 만들 때의 생각에 끌려 같은 허점을 놓칠 수 있습니다. 새 책상에서 시작하는 서브에이전트에게 맡기면 처음 보는 사람에 가까운 눈으로 다시 읽게 할 수 있습니다.

둘째, 많이 읽어야 할 때입니다. 상품 후기 300개를 모두 읽는 일을 메인 에이전트가 직접 하면 책상이 금방 가득 찹니다. 다 읽는 일은 서브에이전트에게 맡기고, 메인 에이전트는 정리된 결과만 받으면 책상을 아낄 수 있습니다.

한 번에 여러 서브에이전트에게 나누어 맡길 수도 있습니다. 예를 들어 한 서브에이전트는 내용이 사실과 맞는지, 다른 서브에이전트는 처음 읽는 사람이 이해하기 쉬운지 살펴보게 하고, 메인 에이전트가 결과를 모읍니다.

6-3

돌려받은 결과도 확인합니다

서브에이전트가 돌려준 의견도 AI의 의견입니다. 맞는 지적도 있지만, 실제와 다른 지적이나 놓친 문제가 섞여 있을 수 있습니다. 지적마다 실제로 그런지 직접 열어 확인하고, 고칠지 말지는 사람이 정합니다.

서브에이전트도 따로 AI를 쓰므로 그만큼 사용량이 더 듭니다. 짧은 문구 하나를 고칠 때까지 맡길 필요는 없습니다. 따로 살펴볼 범위가 분명할 때 맡깁니다.

CodexClaude Code

코딩 에이전트별 안내 Codex와 Claude Code 모두 “서브에이전트에게 맡겨 줘”라고 요청해 쓸 수 있습니다. 자주 맡기는 역할은 미리 정의해 둘 수도 있으니, 방법은 각 공식 안내에서 확인합니다.

핵심 정리

  1. 컨텍스트 윈도우는 AI가 한 번에 참고할 수 있는 정보의 범위로, 책상의 크기에 해당합니다.
  2. 서브에이전트는 건네받은 자료와 기준만 가지고 새 책상에서 일하고 결과만 돌려줍니다. 객관적인 눈이 필요하거나 많이 읽어야 할 때 도움이 됩니다.
  3. 돌려받은 의견도 AI의 의견입니다. 지적마다 직접 열어 확인하고, 고칠지는 사람이 정합니다.

한눈에 정리하기

코딩 에이전트는 하나의 공방입니다

지금까지 살펴본 것을 가구 공방에 빗대어 정리해 봅시다.

공방의 장인은 코딩 에이전트입니다. 장인의 머리에 해당하는 것은 LLM(Large Language Model)으로, 앞의 내용을 보고 다음 글자를 이어 쓰며 무엇을 할지 판단합니다. 장인이 일하는 작업대가 책상, 곧 컨텍스트 윈도우입니다. 지금 참고하는 요청, 파일, 실행 결과가 이 위에 놓입니다.

벽에는 공방의 운영 규칙이 붙어 있습니다. 이것이 AGENTS.md입니다. 장인은 일을 시작할 때 이 규칙부터 읽습니다. 공구 걸이에는 파일 읽기, 파일 수정, 명령 실행 같은 도구가 걸려 있습니다. 장인이 어떤 도구를 쓸지 정하면 도구 호출(Tool Calling)로 실제 작업이 이루어지고, 그 결과가 다시 작업대에 올라옵니다.

선반에는 작업 매뉴얼이 꽂혀 있습니다. 이것이 스킬입니다. 평소에는 표지만 보고, 필요할 때 꺼내 펼쳐 봅니다. 공방에는 바깥으로 난 문도 있습니다. 이 문으로 창고와 거래처, 곧 외부 서비스와 연결됩니다. 이것이 MCP입니다. 옆 작업대에는 외주 작업자가 앉습니다. 장인이 일 하나를 떼어 맡기면 자기 작업대에서 따로 일하고 결과만 돌려줍니다. 이것이 서브에이전트입니다.

공방에서 코딩 에이전트에서 하는 일
벽에 붙은 운영 규칙 AGENTS.md 작업할 때 늘 지킬 지침
공구 걸이 도구 파일 읽기, 수정, 실행 같은 실제 행동
선반의 매뉴얼 스킬 필요할 때 꺼내 보는 작업 절차
바깥으로 난 문 MCP 작업 폴더 밖의 서비스와 연결
옆 작업대의 외주 작업자 서브에이전트 떼어 준 일을 따로 하고 결과만 돌려줌

그래도 확인은 사람이 합니다

공방이 아무리 잘 갖춰져 있어도, 완성된 가구를 받아 직접 써 보고 판단하는 사람은 주문한 사람입니다. 코딩 에이전트도 마찬가지입니다. 기획서로 무엇을 만들지 정하고, 지침으로 일하는 방식을 알려 주고, 결과를 직접 열어 확인하는 일은 사람의 몫입니다.

처음부터 모든 기능을 갖출 필요는 없습니다. 기획서 한 장과 작업 폴더 하나로 시작해 첫 결과물을 만들어 봅니다. 같은 설명을 반복하게 되면 AGENTS.md에 적고, 같은 순서를 반복하게 되면 스킬로 묶고, 다른 눈이 필요해지면 서브에이전트에게 맡깁니다. 불편이 생길 때마다 하나씩 더해 가면 됩니다.
